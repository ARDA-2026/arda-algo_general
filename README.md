# Person in distress Drift Prediction System (Han River)

> 창의적 종합설계 | 인천대학교 임베디드시스템공학과  
> Team ARDA | 2026

---

## 프로젝트 개요

익수자 발생 시 **실시간 표류 위치를 예측**하여 수색·구조 효율을 높이는 시스템입니다.

기존 수난 사고 대응은 구조대원의 경험에 의존하는 경우가 많아, 익수자 위치 특정에 어려움이 있습니다. 따라서 한강 실시간 유속 데이터와 파티클 필터 알고리즘을 결합하여 익수자가 있을 확률이 높은 구역을 히트맵으로 시각화하고, 수색 우선순위 Waypoint를 제공하는 모델입니다.

해당 모델을 한강 - 마포대교 기준으로 진행합니다.

---

## 시스템 동작 흐름

```
[입수 감지]
열화상 카메라로 입수 순간 좌표 포착

↓

[초기 예측]
입수 좌표 + 실시간 유속 데이터 → 파티클 기반 표류 예측 시작

↓

[분기] 카메라/레이더가 재감지 성공?

├── YES → 브라우저 캔버스 클릭으로 관측값 입력 (POST /observation)
│         → 파티클 재수렴 (확률 수렴)
│         → 다시 분기로
│
└── NO  → 파티클이 퍼지면서 불확실성 증가
          → 히트맵 + Waypoint로 수색대 or 드론 유도
```

## 주요 기능

| 기능 | 설명 |
|------|------|
| 실시간 유속 수신 | 한강홍수통제소 API (한강대교 관측소 `1018683`) |
| 유량 → 유속 역산 | `유속 = 유량 / (폭 × 수심)` (마포대교 단면 기준) |
| 파티클 표류 시뮬레이션 | 유속 + 난류(Turbulence) + 확산 계수 적용 |
| 한강 폴리곤 마스킹 | OSM 데이터 기반 한강 본류 폴리곤 추출 (Shapely) |
| 육지 도달 감지 | 파티클이 한강 밖으로 나가는 순간 위치 기록 |
| 누적 히트맵 | 표류 확률 분포를 시간 누적으로 안정적으로 시각화 |
| 수색 우선순위 TOP3 | 확률 높은 구역 순서대로 Waypoint 생성 |
| 관측값 입력 | 브라우저 캔버스 클릭 위치를 파티클 필터 관측값으로 업데이트 |
| 베스트 포인트 궤적 | 가장 확률 높은 지점의 이동 경로 시각화 |
| 육지 도달 포인트 마커 | 익수자가 표류 후 쓰러져 있을 수 있는 육지 지점 표시 |
| 배속 시뮬레이션 | `SPEED` 파라미터로 N분 후 위치를 빠르게 예측 |
| **드론 수색 연동** | Waypoint를 축소 지도 위 Tello 좌표로 변환해 실기체 자율 비행 |

> **히트맵 계산 방식**  
> 축소 지도 영역(실제 450m × 300m)에 **고정된** 가로 30칸 × 세로 20칸 격자(칸당 15m)를 씁니다.  
> 매 스텝 강물 위 파티클을 격자에 누적하되, 과거 기여도를 지수 감쇠(반감기 20초)시켜 **최근 체류 시간** 분포를 만듭니다.
>
> 격자를 파티클 무게중심에 맞춰 매번 재생성하면 서로 다른 좌표계의 카운트를 더하게 되어 누적 확률이 뭉개집니다. 그래서 격자를 지도에 못박았습니다.

> **Waypoint 형식**  
> `{"lon":…, "lat":…, "prob":…}` 형태로 확률 내림차순 정렬합니다.  
> `prob` 은 **누적 확률이 아니라 최근 체류 비율(%)** 입니다.
>
> 확률 상위 칸은 서로 인접해 있어 그대로 쓰면 수색 구역이 한 점에 뭉칩니다.  
> 비최대 억제(NMS)로 **서로 100m 이상 떨어진 지점만** 골라냅니다.

## 기술 스택

| 분류 | 기술 |
|------|------|
| 표류 시뮬레이션 | **NumPy 기반 자체 이류-확산 모델** (외부 표류 모델 미사용) |
| 한강 맵 | OSM (osmnx) + Shapely / GeoPandas |
| 실시간 유속 | 한강홍수통제소 Open API (HRFCO) |
| 백엔드 서버 | **FastAPI + Uvicorn** |
| 실시간 통신 | **WebSocket** (100ms 주기 상태 전송) |
| 프론트엔드 | **HTML5 Canvas + Vanilla JS** (라이브러리 없음) |
| 드론 제어 | **DJI Tello + djitellopy** (UDP 8889) |
| 탐지 하드웨어 | 열화상 카메라 + 서보 모터 (미연동) |
| 좌표 변환 | OpenCV Homography (픽셀 → 실제 좌표, 미연동) |
| 통합 아키텍처 | ROS2 (예정) |

> **용어 주의.** 관측 업데이트는 클릭 지점으로 파티클을 재배치하는 방식이라, 가중치 계산과 리샘플링을 하는 **베이지안 파티클 필터가 아닙니다.** 표류 예측은 몬테카를로 이류-확산 시뮬레이션입니다. 발표 자료 작성 시 참고하세요.

## 실행 전 설정

`hanriver.py` 에서 다음 값을 필요에 따라 변경하세요:

```python
# 난류 강도 (0.0 ~ 1.0)
TURBULENCE = 0.3

# 배속 (1프레임당 시뮬레이션 스텝 수)
# SPEED = 1   →  약 1.5~2배속 (드론 실기 연동용 기본값)
# SPEED = 60  →  약 90배속 (화면으로 빠르게 훑어볼 때)
#
# 드론 연동 시 반드시 1 로 두세요.
# 60 이면 드론이 이륙하기도 전에 파티클이 지도를 벗어납니다.
SPEED = 1

# 입수 지점 (실제: 열화상 카메라 감지 좌표)
MAPO_LAT = 37.540
MAPO_LON = 126.907
```

### 유속 모드 전환

#### 기본값 — 고정 유속 (git clone 직후 바로 실행 가능)

API 키 없이도 즉시 실행됩니다.

```python
# hanriver.py 의 유속 설정 부분 (기본 상태)
velocity_x = -1.5   # m/s, 서쪽 방향 (한강 평균)
velocity_y =  0.05  # m/s, 남쪽 방향

# velocity_x, velocity_y = get_velocity()  ← 주석 처리된 상태
```

#### API 모드 — HRFCO 실시간 유속

**Step 1.** 한강홍수통제소에서 API 키 발급  
→ [https://www.hrfco.go.kr/web/openapiPage/openApi.do](https://www.hrfco.go.kr/web/openapiPage/openApi.do)

**Step 2.** `.env` 파일에 키 입력

```bash
# .env
API_KEY=발급받은키를여기에입력
```

**Step 3.** `hanriver.py` 유속 설정 부분을 아래처럼 변경

```python
# velocity_x = -1.5   ← 이 두 줄을 주석 처리
# velocity_y =  0.05

velocity_x, velocity_y = get_velocity()  # ← 이 줄 주석 해제
```

> API 호출 실패 시 자동으로 기본값(`-0.05 m/s`)으로 대체되어 시뮬레이션은 계속 실행됩니다.

## API 엔드포인트

| 메서드 | 경로 | 설명 |
|--------|------|------|
| `GET` | `/` | 브라우저 시각화 페이지 |
| `GET` | `/state` | 현재 시뮬레이션 상태 (JSON) |
| `GET` | `/river-geojson` | 한강 폴리곤 GeoJSON |
| `POST` | `/observation` | 관측값(브라우저 클릭) 입력 `{"lon": ..., "lat": ...}` — 대기 중이면 그 지점에서 시작, 이미 시작됐으면 파티클만 재수렴 |
| `POST` | `/report` | arda-bringup의 기존 `report_url`(`send_fall_report()`)이 그대로 호출. `{"lat","lon","timestamp"?,"thermal_image_base64"?,"confirmed"?}` — 이미지 없는 호출/`confirmed=true`는 `/observation`과 동일하게 처리(대기 중이면 시작, 아니면 재수렴), 이미지가 있으면 항상 최신 열화상으로 저장해 시각화 |
| `POST` | `/reset` | 시뮬레이션을 대기 상태로 되돌림(기본 입수 지점 복원, 파티클 정지) — 다음 낙하 판정까지 계산 안 함. 비행 중엔 `409` |
| `WS` | `/ws` | WebSocket 실시간 상태 스트림 |
| `POST` | `/takeoff` | 드론 이륙 지점 지정 `{"lon": ..., "lat": ...}` |
| `POST` | `/takeoff/reset` | 이륙 지점을 기본 위치로 복원 |
| `POST` | `/map` | 지도 영역 변경 `{"width_m":3,"height_m":2,"scale":150,"east_m":50}` |
| `POST` | `/map/reset` | 지도 설정 기본값 복원 |
| `GET` | `/mission` | Waypoint를 Tello 기체좌표로 변환 (`?top_n=3`) |
| `POST` | `/drone/connect` | 기체 연결 `{"dry_run": true}` |
| `POST` | `/drone/start` | **자동 순회** 실행 `{"top_n":3,"speed":30,"hover_sec":3}` |
| `POST` | `/drone/takeoff` | **수동** — 이륙만 (착륙하지 않고 대기) |
| `POST` | `/drone/goto` | **수동** — 한 지점으로 이동 `{"lon":…,"lat":…,"speed":30}` |
| `POST` | `/drone/home` | **수동** — 이륙 지점 복귀 (`?speed=30`) |
| `POST` | `/drone/path/reset` | 지도에 남은 경로 표시만 지움 (비행 무관) |
| `POST` | `/drone/land` | 즉시 착륙 (비상 정지) |
| `GET` | `/drone/status` | 배터리·진행률·종료 사유·`airborne`·`idle_left` |

> `/takeoff` 와 `/map` 은 **비행 중에는 `409`** 로 거부됩니다. 좌표계가 바뀌면 드론의 지령 위치 누적이 통째로 어긋나기 때문입니다.

## 조작 및 지도 제어 방법

| 구분 | 조작 / 단축키 | 기능 |
|------|----------------|------|
| **관측값 입력** | 클릭 (드래그 제외) | 클릭 위치를 관측값으로 입력 → 파티클 재수렴 |
| **지도 이동** | 마우스 드래그 | 지도 화면 자유 이동 (무제한) |
| **지도 줌** | 스크롤 휠 | 마우스 커서 위치 기준 줌 인/아웃 |
| **전체 보기** | 🏠 전체 버튼 / `R` 키 | 한강 전체 범위로 카메라 복귀 |
| **지도 영역** | 🗺 지도 영역 버튼 / `M` 키 | 실물 지도 범위에 맞춤 (서버 접속 시 자동 적용) |
| **따라가기** | 📍 따라가기 버튼 / `F` 키 | 최고 확률 지점을 화면 중앙에 자동 유지 |
| **버튼 줌** | `＋` / `－` 버튼 / `+`, `-` 키 | 화면 중앙 기준 확대 / 축소 |
| **패닝** | 화살표 키 (`↑`, `↓`, `←`, `→`) | 화면 15% 단위 영역 이동 |
| **테마 전환** | ☀/☾ 버튼 / `T` 키 | 다크 ↔ 라이트. 선택은 브라우저에 저장됨 |
| **이륙 지점 지정** | 🚁 버튼 → 지도 클릭 | 클릭 위치가 드론 좌표계의 (0,0) 이 됨. `Esc` 취소 |
| **비상 착륙** | 🔴 착륙 버튼 / `L` 키 / `Esc` | 즉시 착륙. 항상 활성 |

> 이륙 지점 지정 모드에서는 **관측값 입력이 걸리지 않습니다.** 실수로 시뮬레이션이 리셋되지 않게 막아둔 것입니다.

## 화면 구성

| 요소 | 모양 | 설명 |
|------|------|------|
| 입수 지점 | 빨간 별 ★ | 익수자 입수 좌표 (지리 기준점) |
| **드론 이륙 지점** | **연두 헬리패드 H** | **Tello 기체 좌표의 (0,0)** |
| 실물 지도 경계 | 파선 사각형 | 이 밖으로는 드론이 못 나감. 바깥은 어둡게/희게 처리 |
| 파티클 | 주황 점 | 표류 예측 파티클 |
| 히트맵 | 자동 스케일 컬러맵 | 최근 체류 확률 분포 (우하단 컬러바 참조) |
| 최고 확률 지점 | 청록 다이아몬드 ◆ | 현재 가장 확률 높은 격자 칸 |
| 표류 궤적 | 청록 점선 | 최고 확률 지점 이동 경로 |
| 수색 우선순위 | 번호 붙은 원 | TOP 1/2/3… (테마별 색상) |
| 비행 경로 | 초록 실선 / 흰 파선 | **모드에 따라 다릅니다** (아래) |
| 건너뛴 레그 | 회색 점선 + ✕ | 자동 모드에서 이동량 20cm 미만이라 실행 안 함 |
| 드론 지령 위치 | 파란 셰브론 ▲ | **측정값이 아니라 명령 누적값** |
| 육지 도달 포인트 | 보라 X | 파티클이 육지에 닿은 지점 |
| 관측값 | 초록 삼각형 ▲ | 캔버스 클릭으로 입력한 관측값 |

#### 경로 표시는 모드마다 다릅니다

| | **수동 이동** | **자동 순회** |
|---|---|---|
| 초록 실선 | **드론이 실제로 지나간 자취** | 완료한 레그 |
| 파선 | 이동 중 — 마지막 지점 → 목표 | 아직 안 간 예정 레그 |
| 지점 표시 | 다녀온 waypoint 에 **✓** | 번호 원만 |

수동 모드는 경로가 미리 정해지지 않으므로 "예정 경로"라는 개념이 없습니다. 서버가 지령 위치의 자취(`status.path`)를 기록하고, 화면은 그것을 그대로 그립니다. 자취는 최근 60개 지점까지 남고, **이륙할 때 초기화**되며 `지우기` 버튼으로 언제든 비울 수 있습니다.

> **히트맵 색상은 자동 스케일입니다.** 시작 직후엔 최고 칸이 50%를 넘고 정상 상태에선 1~3%라 고정 범위로는 양쪽을 못 맞춥니다. 우하단 컬러바에 현재 최댓값이 표시됩니다.
>
> 컬러맵은 테마에 따라 **방향이 뒤집힙니다** — 다크는 고확률이 밝게(inferno), 라이트는 고확률이 진하게(YlOrRd). 배경 대비 휘도가 값과 함께 멀어져야 눈에 띄기 때문입니다.

### 지도 · 격자 · Waypoint

**지도 설정은 브라우저 우측 `실물 지도` 카드에서 바꿀 수 있습니다.** 아래는 기본값입니다.

| 파라미터 | 기본값 | 설명 |
|----------|--------|------|
| `MAP_SCALE` | 150 | 축척 1:150 |
| `MAP_PRINT_W` / `MAP_PRINT_H` | 3.0m / 2.0m | **실물** 지도 크기 |
| (파생) `MAP_W_M` / `MAP_H_M` | 450m / 300m | 지도가 덮는 실제 영역 = 실물 × 축척 |
| `MAP_EAST_M` | 50m | 입수 지점을 지도 동쪽 끝에서 안쪽으로 둘 거리 |
| `GRID_CELL_M` | 15m | 격자 한 칸이 덮을 실제 거리 (칸 수는 자동 계산) |
| `TAKEOFF_MARGIN_MAP_M` | 0.30m | 이륙 지점을 지도 동쪽 변 **바깥**으로 둘 실물 거리 |
| `HIST_HALF_LIFE_SEC` | 20초 | 히트맵 망각 반감기 |
| (자동) `NMS_MIN_DIST_M` | 100m | Waypoint 최소 간격. **지도 크기에 비례** (`MAP_W_M / 4.5`) |

지도를 바꾸면 아래가 전부 다시 계산됩니다:

- 격자 — 칸이 **정사각형에 가깝게** 유지되도록 칸 수 자동 산출
- 누적 히트맵 — **리셋** (좌표계가 바뀌므로 이전 누적은 무의미)
- NMS 간격 — 비례 조정. 고정 100m로 두면 작은 지도에서 waypoint가 1개만 남습니다
- 이륙 지점 — 기본값이었으면 따라 이동. **직접 찍은 건 유지**
| `NMS_MAX_COUNT` | 10 | Waypoint 최대 개수 |

## Waypoint 외부 연동

서버가 실행 중이면 아래 방법으로 Waypoint 데이터를 꺼내 쓸 수 있습니다.

### Waypoint JSON 형식

```json
[
  { "lon": 126.90430, "lat": 37.53980, "prob": 8.5 },
  { "lon": 126.90360, "lat": 37.54010, "prob": 6.2 },
  { "lon": 126.90210, "lat": 37.53950, "prob": 5.1 }
]
```

- `lon` / `lat`: 경도 / 위도 (WGS84)  
- `prob`: 해당 격자 칸의 누적 표류 확률 (%)  
- 확률 내림차순 정렬, 최대 10개 제공

---

### 방법 1 — HTTP GET (가장 간단)

```python
import requests

data = requests.get("http://localhost:8000/state").json()
waypoints = data["waypoints"]          # 리스트, 확률 내림차순

for i, wp in enumerate(waypoints[:3], 1):
    print(f"Top{i}: ({wp['lat']:.5f}, {wp['lon']:.5f})  {wp['prob']:.1f}%")
```

---

### 방법 2 — WebSocket (실시간 스트림)

매 100ms마다 최신 상태를 수신합니다.

```python
import asyncio, json, websockets

async def watch_waypoints():
    async with websockets.connect("ws://localhost:8000/ws") as ws:
        while True:
            data = json.loads(await ws.recv())
            waypoints = data["waypoints"]
            print(waypoints[:3])

asyncio.run(watch_waypoints())
```

```bash
pip install websockets
```

### 방법 3 — ROS2 연동 예시

```python
import requests
from geometry_msgs.msg import PoseArray, Pose

def publish_waypoints(pub):
    data = requests.get("http://localhost:8000/state").json()
    pose_array = PoseArray()
    for wp in data["waypoints"][:10]:
        pose = Pose()
        pose.position.x = wp["lon"]
        pose.position.y = wp["lat"]
        pose_array.poses.append(pose)
    pub.publish(pose_array)
```

## 드론 수색 연동 (DJI Tello)

예측된 Waypoint로 **Tello가 축소 지도 위를 실제로 비행**합니다.

### 왜 축소 지도인가

Tello에는 **GPS가 없습니다.** `go x y z speed`(현재 위치 기준 상대 이동, cm)만 있습니다. 게다가 실제 탐색 영역은 수백 미터라 실물 크기로는 날 수 없습니다.

그래서 **실제 450m × 300m 를 3m × 2m 축소 지도(축척 1:150)로 옮겨** 그 위를 비행시킵니다.

### 실물 배치

```
                    지도 북쪽 (N)
      ┌──────────────────────────────────────────┐  ─┐
      │                                          │   │
      │                                     ★    │  100cm
  서  │                                  입수지점 │  ─┤  2.0 m       🚁
 (W)  │                                          │  100cm      이륙 지점
      │                                          │   │           (0,0)
      └──────────────────────────────────────────┘  ─┘
      |←─────────────── 3.0 m ─────────────→|33.3cm|←30cm→|
                                                          동 (E)
```

| 항목 | 값 |
|------|-----|
| 실물 지도 | 3.0m (동서) × 2.0m (남북) — 브라우저에서 변경 가능 |
| 축척 | 1:150 (실제 450m × 300m) |
| 입수 지점 ★ | 지도 동쪽 끝에서 **33.3cm** 안쪽, 남북 **정중앙** |
| **이륙 지점 🚁** | 지도 동쪽 변에서 **바깥으로 30cm** (기본값) |
| 기수 방향 | **지도 북쪽 고정. 비행 중 회전 금지** |
| 필요 공간 | 최소 4m × 3m, 권장 5m × 4m (천장 2.5m 이상) |

**드론은 지도 위가 아니라 옆에 놓습니다.**

**기수 정렬이 가장 중요합니다.** 회전하면 yaw 오차가 이후 모든 이동에 누적되는데, 일반 Tello는 실제로 몇 도 돌았는지 알려주지 않아 보정이 불가능합니다. 지도에 `N` 화살표를 표시해두고 거기 맞춰 내려놓으세요.

> 인쇄 지도는 광류 센서에 유리합니다. 무늬가 풍부해 단색 바닥보다 위치 추정이 안정적입니다.

### 좌표계 — 기준점이 두 개입니다

**섞으면 안 됩니다.**

| 기준점 | 역할 |
|--------|------|
| **입수 지점** (`origin`) | 지도 사각형이 이 점 기준으로 정의됨 → **"지도 밖인가" 판정** |
| **이륙 지점** (`takeoff`) | Tello는 이륙 자리를 (0,0) 으로 삼는 상대 좌표계 → **`go` 명령 계산** |

```
Tello 기체축 (기수가 북일 때)
    x (forward) = 북 (North)
    y (left)    = 서 (West)   ← 동쪽은 음수
```

`go` 명령의 y 부호는 Tello SDK에도 djitellopy에도 문서화되어 있지 않습니다. 방향이 명확한 `left` 명령을 기준자로 삼아 **실기 검증한 결과 좌(+) = 항공 표준 FLU** 가 맞았습니다.

#### 왜 둘을 분리했나

1. **입수 지점은 열화상 카메라가 감지하는 값**이라 사고마다 달라집니다. 이륙 자리는 물리적으로 고정돼야 합니다.
2. **둘이 겹치면 WP1이 스킵됩니다.** 시작 직후엔 파티클이 입수 지점에 몰려 있어 WP1 ≈ 이륙 지점이 되고, 이동량이 Tello 최소값(20cm) 미만이라 "수색 우선순위 1번"을 건너뛰게 됩니다.
3. 드론이 지도의 입수 지점 표식(★)을 깔고 앉습니다.

분리 전후 실측:
```
이전:  leg1 -> WP1   5.3cm   skip=True    <- 최우선 지점을 건너뜀
현재:  leg1 -> WP1  65.2cm   skip=False
```

브라우저 툴바 **`🚁 이륙 지점`** 버튼 → 지도 클릭으로 언제든 바꿀 수 있고, 드론 카드의 `기본` 버튼으로 되돌립니다.

### 실행

**창 1 — 서버**
```powershell
python hanriver.py
```

**창 2 — 드론**
```powershell
python fly.py            # 실기체 비행
python fly.py --dry      # 드론 없이 예행 연습
python fly.py --yes      # 확인 프롬프트 생략
```

| 옵션 | 기본값 | 설명 |
|------|--------|------|
| `--top` | 3 | 수색 지점 수 (1~10) |
| `--speed` | 30 | 비행 속도 cm/s (10~100) |
| `--hover` | 3.0 | 지점별 정지 시간 (초) |
| `--wait` | 100 | 파티클 확산 최대 대기 (초) |

`fly.py` 가 하는 일:

1. 서버 확인
2. **WP1이 이륙 지점에서 충분히 멀어질 때까지 대기** — 서버 켜자마자 날리면 파티클이 입수 지점에 몰려 있어 WP1이 원점과 겹치고, Tello 최소 이동거리 20cm 미만이라 최우선 수색 지점을 건너뛰게 됩니다
3. 기체 연결 + 배터리 확인
4. 미션 미리보기 + 경고 표시
5. 확인 후 비행, 진행 상황 실시간 출력
6. 종료 사유 판정

### 운용 모드 — 수동 / 자동

목적에 따라 브라우저에서 골라 씁니다.

| | **수동 이동** (기본) | **자동 순회** |
|---|---|---|
| 동작 | 지점을 골라 `이동` 누를 때만 감 | TOP1→2→3→복귀 자동 실행 |
| 이동 후 | **계속 떠 있음** | 순회 끝나면 착륙 |
| 착륙 | 명시적으로 눌러야 함 | 자동 |
| 쓰임 | 실제 운용. 조작자가 판단해 보냄 | 시연. 예측 결과를 한 번에 보여줌 |

**수동을 기본으로 둔 이유:** 드론에 자체 탐지 센서가 없어 자율 이동의 근거가 시뮬레이션뿐입니다. 조작자가 지점을 선택해 보내는 편이 현재 구성에 더 맞습니다. 자율 순회는 기체에 추적 기능이 붙은 뒤에 타당해집니다.

#### 수동 모드 흐름

```
[ 이륙 ]  ← 먼저 떠야 이동 버튼이 활성화됨
  1  1.29%  x+152 y+272  [이동]
  2  0.99%  x +32 y+182  [이동]
  3  0.93%  x +82 y+272  [이동]
[ 이륙 ] [ 복귀 ] [ 지우기 ]
🔴 착륙   ← 끝낼 때
```

- **복귀** — 이륙 지점으로 이동 (착륙은 안 함)
- **지우기** — 지도에 남은 경로 표시만 지움. 비행 상태와 지령 위치는 그대로이고, 현재 위치가 새 시작점이 됩니다

> ⚠️ **떠 있는 채로 방치하면 90초 뒤 자동 착륙합니다.** 배터리가 다해 추락하는 걸 막기 위한 것으로, 남은 시간이 버튼 아래에 표시됩니다. 이동할 때마다 초기화됩니다.

이동 명령은 다음을 만족해야 실행됩니다 — 이륙 상태 ∧ 목표가 지도 안 ∧ 이동량 20~500cm ∧ 배터리 ≥30%. 위반하면 `409` 와 함께 사유가 표시됩니다.

### 브라우저에서 조종하기

`http://localhost:8000` 우측 **드론 수색** 카드에서 전부 가능합니다.

```
[DRY RUN] [실기체]         ← 기본은 DRY RUN. 실기체는 명시적으로 전환
[수동 이동] [자동 순회]     ← 기본은 수동
[ 연결 ]
이륙 지점  동63 북0 cm  [기본]
상태  hovering   배터리 ▓▓▓▓░ 79%
진행  ▓▓▓░░ 2/4
속도[30] …
  1  1.29%  x+152 y+272  [이동]
  2  0.99%  x +32 y+182  [이동]
  3  0.93%  x +82 y+272  [이동]
[ 이륙 (DRY RUN) ]  [ 복귀 ]
72초 후 자동 착륙
이벤트 ────────────────
[20:10] 기체 연결됨. 배터리 79%
[20:11] [수동] 이륙 완료 - 대기 중
```

| | |
|---|---|
| **실기체 발진** | 1클릭 → 주황색 `정말 이륙? (3)` → **3초 안에 한 번 더 클릭** |
| **비상 착륙** | 캔버스 우측 상단 🔴 버튼. **항상 활성**, 확인 없음 |
| **차단 시** | 버튼 아래에 사유가 문장으로 표시됨 (`배터리 부족 (24% / 최소 30%)` 등) |

자동 순회의 발진 조건은 [tello_driver.py](tello_driver.py) 의 검사를 그대로 미러링합니다 — 연결됨 ∧ 미실행 ∧ 모든 waypoint 지도 안 ∧ 배터리 ≥30% ∧ 모든 레그 ≤500cm.

> 네이티브 `confirm()` 대신 2단계 arm을 쓴 이유: 모달이 페이지 전체를 막으면 **정작 눌러야 할 비상 착륙 버튼까지 못 누르게 됩니다.**

### 개별 명령

```powershell
python drone_cli.py status     # 상태
python drone_cli.py mission    # 좌표 변환만 확인 (드론 불필요)
python drone_cli.py land       # 비상 착륙
python drone_cli.py watch      # 실시간 감시
```

> **비상 착륙(`drone_cli.py land`)을 다른 창에 미리 쳐두고 Enter 대기 상태로 두세요.**  
> `fly.py` 의 `Ctrl+C` 는 그 프로세스가 살아있어야 동작합니다.

### 안전장치

| 조건 | 동작 |
|------|------|
| 배터리 30% 미만 | 이륙 거부 |
| 지도 밖 waypoint | **미션 거부** |
| 레그 500cm 초과 | 미션 거부 |
| 레그 20cm 미만 | 해당 레그 건너뜀 |
| 예외 발생 | `finally` 에서 **무조건 착륙** |
| `/drone/land` | 즉시 중단 후 착륙 |
| **수동 모드 90초 유휴** | **자동 착륙** (배터리 소진 추락 방지) |
| 수동 모드 이동 실패 | 즉시 착륙 |

### 미션 종료 사유

`GET /drone/status` 의 `result` 필드로 판정합니다.

| 값 | 의미 |
|----|------|
| `completed` | 정상 완료 — 모든 레그 실행 후 이륙 지점 복귀 |
| `aborted` | 사용자 중단 |
| `error` | 예외 발생 (착륙 실패 포함) |
| `incomplete` | 레그 일부 미실행 |

> ⚠️ `completed` 는 **"명령을 다 보냈다"**는 뜻이지 **"정확한 좌표에 도달했다"**는 뜻이 아닙니다.  
> 일반 Tello는 절대 위치 센서가 없어 실제 오차를 알 수도, 보정할 수도 없습니다.  
> 실내 광류 드리프트는 통상 ±20~50cm이며, Waypoint 간 최소 간격(지도상 67cm)보다 작아 구역 구분에는 지장이 없습니다.

### 네트워크

Tello는 자체 WiFi AP를 띄웁니다. 노트북을 `TELLO-XXXXXX` 에 연결하면 **인터넷이 끊기지만** 다음 이유로 문제없습니다.

| 인터넷 필요 항목 | 상태 |
|------------------|------|
| OSM 폴리곤 다운로드 | `cache/` 에 캐시됨 — 오프라인 OK |
| HRFCO 실시간 유속 | 기본값이 고정 유속이라 무관 |
| FastAPI ↔ 브라우저 | `localhost` — 네트워크 무관 |

**노트북 1대만으로 완결됩니다.** 다른 기기(Jetson·태블릿)를 붙일 때만 USB WiFi 동글이 추가로 필요합니다.

#### 어댑터 배치 — 실측으로 확정된 사항

| 어댑터 | 담당 |
|--------|------|
| **USB 동글** | **Tello** |
| 내장 WiFi | 인터넷 / Jetson |

⚠️ **직관과 반대입니다.** 좋은 어댑터를 드론에 주고 싶지만, 테스트 환경의 **Intel AX211은 Tello를 스캔 목록에서 아예 걸러냅니다** — 2.4GHz 대역 BSSID를 91개나 잡으면서 `TELLO-XXXXXX` 만 안 보입니다. Tello AP가 **개방형(암호화 없음) 802.11g** 이라 최신 드라이버가 숨기는 것으로 보입니다.

**본인 환경에서 반드시 확인하세요:**
```powershell
netsh wlan show networks interface="Wi-Fi"    | findstr TELLO
netsh wlan show networks interface="Wi-Fi 2"  | findstr TELLO
```
**TELLO가 보이는 어댑터**를 드론에 쓰면 됩니다.

#### Jetson 연동 시

서버는 이미 `0.0.0.0:8000` 바인딩이라 코드 변경이 필요 없습니다. 다만 **Windows 방화벽이 막습니다**:

```powershell
New-NetFirewallRule -DisplayName "ARDA drift server 8000" `
  -Direction Inbound -Protocol TCP -LocalPort 8000 `
  -Action Allow -Profile Private,Domain -RemoteAddress LocalSubnet

Set-NetConnectionProfile -InterfaceAlias "<통신용 어댑터>" -NetworkCategory Private
```

**검증은 반드시 다른 기기에서** — 노트북에서 자기 IP로 접속하면 Windows가 루프백으로 우회해 방화벽을 안 탑니다. 휴대폰으로 `http://<PC_IP>:8000/state` 를 열어 JSON이 나오면 Jetson도 됩니다.

## 문제 해결

실제 개발·테스트에서 부딪힌 것들입니다.

### 드론이 안 난다

**① 이벤트 로그부터 보세요.** `GET /drone/status` 또는 브라우저 드론 카드 하단.

| 로그 상태 | 의미 | 조치 |
|----------|------|------|
| `기체 연결됨` 한 줄뿐 | **미션 요청이 서버에 안 들어옴** | 브라우저 문제 (아래 ②) |
| `이륙` 이후 `go` 명령 있음 | 명령은 나감 | 무선 링크 / 기체 문제 |
| `Aborting command ... 7 seconds` | **응답 유실** | 신호 강도 확인 |

**② 브라우저 캐시.** UI를 고쳐도 옛 JS가 돌면 그대로입니다. `Ctrl + Shift + R` 로 강제 새로고침하세요.
서버에 `no-store` 헤더를 넣어두었으니 **서버를 재시작한 뒤로는** 일반 새로고침으로도 최신이 옵니다.

**③ 실기체 모드인지 확인.** 기본값은 `DRY RUN` 이라 명령이 기체로 안 나갑니다.

**④ 2단계 arm.** `실기체` 모드는 **3초 안에 두 번 클릭**해야 발진합니다. 한 번만 누르면 자동 취소됩니다.

**⑤ 검증된 경로로 우회.** UI가 의심되면 `python fly.py --speed 20` 으로 먼저 날려보세요. 드론 문제인지 UI 문제인지 즉시 갈립니다.

### 무선 링크

```powershell
netsh wlan show interfaces | findstr /C:"SSID" /C:"Signal"
ping 192.168.10.1
```

**신호 50% 이상**이 나와야 정상입니다. 실측에서 5%일 때는 결합은 되는데 패킷이 전혀 안 갔습니다.

`ping` 이 안 되면 SDK로 직접 확인하세요 — `b'ok'` 가 나와야 합니다:
```powershell
python -c "import socket;s=socket.socket(2,2);s.bind(('',8889));s.settimeout(5);s.sendto(b'command',('192.168.10.1',8889));print(s.recvfrom(1024))"
```

| 증상 | 원인 |
|------|------|
| `associating` 에서 멈춤 | 드론이 멀거나 전원/배터리 문제 |
| 결합은 됐는데 무응답 | **드론 재부팅 + 배터리 교체** |
| 붙었다 끊겼다 반복 | 거리. 노트북을 드론 1m 이내로 |
| Windows가 자꾸 다른 WiFi로 되돌림 | `netsh wlan set profileparameter name="<원래WiFi>" connectionmode=manual` |

**배터리를 오래 켜두면 방전됩니다.** 30% 미만이면 이륙이 거부되고, 그보다 낮으면 무선도 불안정해집니다.

### 서버

| 증상 | 원인 |
|------|------|
| `[Errno 10048] bind ... 8000` | 이전 서버가 안 죽음. 프로세스 정리 후 재시도 |
| 서버가 아예 안 뜸 | 인터넷 없는데 `cache/` 가 없음. **이 폴더 지우지 마세요** |
| python 프로세스가 2개로 보임 | **정상**입니다. Store Python 기반 venv는 런처가 실제 인터프리터를 자식으로 띄웁니다 |

### 재연결

한 번 비행한 뒤 다시 연결하면 실패하던 문제가 있었습니다. djitellopy가 `Tello()` 생성 시 전역 `drones` 딕셔너리에 등록하고 `__del__ → end()` 에서 지우는데, 정리 없이 재대입하면 **새 인스턴스의 등록을 옛 인스턴스의 소멸자가 지워버립니다.** 응답 수신 스레드가 `address not in drones` 로 모든 응답을 버리게 되죠.

[tello_driver.py](tello_driver.py) 의 `connect()` 에서 이전 인스턴스를 명시적으로 `end()` 한 뒤 새로 만들도록 고쳤습니다. **서버 재시작 없이 몇 번이든 재연결됩니다.**
